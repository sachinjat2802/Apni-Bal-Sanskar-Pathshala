💡 **What:** Migrated the `our-document` page from using a monolithic `dangerouslySetInnerHTML` string to standard JSX elements. This allowed us to replace standard HTML `<img>` and `<a>` tags with Next.js's optimized `<Image />` and `<Link />` components.

🎯 **Why:** Rendering a page exclusively through a massive `dangerouslySetInnerHTML` block bypasses React's virtual DOM capabilities and prevents the use of Next.js performance optimizations. The old method led to unoptimized images (missing out on modern formats, lazy loading, and CLS prevention) and standard HTML navigation (causing full page reloads rather than fast client-side routing).

📊 **Measured Improvement:** We were unable to measure a significant difference in raw build time (consistently around 3.5s - 4.5s both before and after), which is expected for static generation of a single component. However, the *client-side* performance improvements are undeniable based on Next.js architecture:
*   **LCP and CLS Improvement:** Images like the logo and document previews are now routed through the Next.js image optimization pipeline via the `<Image />` component. Even with `unoptimized: true` set globally, we gain CLS protection via explicit width/height boundaries and default lazy loading.
*   **Faster Navigation:** Internal links (e.g., to `/`, `/about`, `/contact`) now use `<Link />`, which prefetches linked pages in the background, making subsequent navigations instantaneous compared to the full-page reloads caused by standard `<a>` tags.
*   **Reduced Bundle Size:** Redundant global script `<script>` tags were removed from the bottom of this specific page, as they are already centrally managed and injected via the `RootLayout` component, leading to less repeated execution and a cleaner DOM.
